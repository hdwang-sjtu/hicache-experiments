# 8K–128K Prefix 性能外推（2026-11-01）

## 目标和配置

这一轮只测性能：保留原始 RoPE 算法和 `rope_theta=1000000`，扩大位置范围，不启用 YaRN，不修改权重文件，不评估语言模型质量。
保留缓存命中、传输字节数、无回撤、正常结束及相同输入输出 token 一致性检查，避免把缓存错误当作性能结果。
每组 10 次的 P95 是有限样本统计，不能据此声称生产尾延迟稳定。

目标 P 为 8K 到 128K、步长 8K，固定 S=128、输出 1 token；Cold/L1/L2 各 10 次，共 480 个正式样本。
最大请求为 131201 tokens；L1 可能同时保留预热和测量后缀，容量验收至少预留 131329 个 GPU KV 槽位。
请求上下文和目标 GPU KV 池均设为 135168，CPU 池为 32 GB（十进制），静态显存预算从 0.85 开始。
若实际 GPU KV 容量不足，改为 0.90 重新启动验收；仍不足则保留诊断并停止，不降低精度或缩小 P。

## 运行步骤

在宿主机启动专用服务。GPU 3 是本轮实际选择，复现时应先确认目标卡空闲；RUN_ID 和结果目录必须使用新名字：

```bash
GPU=3 HICACHE=1 FORWARD_TIMING=1 \
CONTEXT_LENGTH=135168 MAX_TOTAL_TOKENS=135168 \
HICACHE_SIZE=32 MEM_FRACTION=0.85 \
RUN_ID=prefix128k-demo CONTAINER_NAME=hicache-prefix128k \
  bash launch_server.sh --json-model-override-args '{"max_position_embeddings":135168}'
```

先验收最大点，诊断样本不进入正式统计：

```bash
docker exec --user "$(id -u):$(id -g)" hicache-prefix128k \
  python /experiment/run_experiment.py run \
  --tokenizer /model --output-dir /results/prefix128k-profile-demo \
  --prefix-lengths 128k --suffix-lengths 128 --output-length 1 \
  --groups cold l1 l2 --repeats 1 --gpu-timing --profile --no-plot \
  --note 'Unscaled RoPE extrapolation; model quality not evaluated'

docker exec --user "$(id -u):$(id -g)" hicache-prefix128k \
  python /experiment/run_experiment.py analyze-traces /results/prefix128k-profile-demo
```

128K 的 L2 应为 device=0、host=131072，已完成的 KV payload 为 19,327,352,832 字节，即 18 GiB。
验收后在相同服务上关闭 Profiler，运行完整扫描：

```bash
docker exec --user "$(id -u):$(id -g)" hicache-prefix128k \
  python /experiment/run_experiment.py run \
  --tokenizer /model --output-dir /results/prefix-scan-128k-demo \
  --prefix-lengths 8k 16k 24k 32k 40k 48k 56k 64k 72k 80k 88k 96k 104k 112k 120k 128k \
  --suffix-lengths 128 --output-length 1 --groups cold l1 l2 --repeats 10 --gpu-timing \
  --note 'Unscaled RoPE extrapolation; model quality not evaluated'
```

每个 P 先对三组各做一次运行预热，随后随机化组顺序；每个正式样本都重新构造缓存状态。
固定 S 时，`latency.png` 和 `timing.png` 都以 P 为横轴，延迟图使用对数纵轴。
`--note` 会进入配置及图表，明确本轮为未缩放 RoPE 外推；旧的固定 P / 扫描 S 绘图继续支持。
结果目录独立保存；历史短上下文实验不能与本轮数据合并计算分位数。
完成或失败均保留原始样本和日志，完成复核后停止专用实验容器。

## 结果和证据

正式结果：[prefix-scan-128k](../../results/prefix-scan-128k/)；最大点诊断：[prefix128k-profile](../../results/prefix128k-profile/)；启动证据：[prefix128k-server-v1](../../results/prefix128k-server-v1/)。
正式扫描为 18:21–21:35，独立收尾于 21:36 完成（Asia/Shanghai）。
实际 GPU KV 池为 135168 tokens，CPU 池为 217014 tokens；`MEM_FRACTION=0.85` 已满足容量，无需提高到 0.90。
下面列出部分长度的中位数，单位 ms；完整 16 个长度的 Median/P95 见 `summary.csv`。

| P | Cold 首 token | L1 首 token | L2 首 token | L2 H2D 区间 | L1 forward 区间 |
|---|---:|---:|---:|---:|---:|
| 8K | 1186.58 | 29.46 | 53.43 | 49.13 | 26.46 |
| 32K | 6370.18 | 39.25 | 192.57 | 186.79 | 34.79 |
| 64K | 16822.63 | 55.85 | 386.61 | 379.13 | 47.38 |
| 96K | 31337.18 | 72.27 | 572.92 | 563.34 | 64.88 |
| 128K | 49990.73 | 90.93 | 757.99 | 744.37 | 81.46 |

160 个正式 L2 样本全部满足 device=0、host=P、恢复 payload=P×147456 字节，最大点为 18 GiB。
独立校验复算了输入哈希、原始响应、原始 H2D/forward 指标差值、前后槽位、输出一致性和全部分位数；
176 次完成的 demote 包含每个长度的运行预热。最大点的三组诊断还交叉核对了 CPU/CUDA correlation、GPU annotation 和区间交集。
正式扫描约 3 小时 14 分钟；`completion.json` 记录独立收尾完成和容器停止，`gpu-after.txt` 记录 GPU 3 已回到 17 MiB、0% 利用率。

固定 S=128 时，H2D 区间随 P 近似线性增长；长 Prefix 下 L2 forward 区间接近 H2D 区间，恢复加载限制响应速度。
128K 的 L2 相比 Cold 首 token 中位数约快 66 倍，但仍明显慢于 GPU L1；这些结果不能用于证明模型的长上下文质量。
Cold 的部分样本存在较大的非 forward 区间开销：128K 的服务端首 token P95 为 58.16 秒，forward GPU 区间 P95 约 48.77 秒。
该差异尚未进一步归因，保留在原始数据和 P95 中，不能把 Cold 首 token 延迟全部称作 GPU Prefill 时间。

## 性能隔离复核与限制

会话中断期间 Driver 和服务持续运行，请求和原始指标未中断落盘，完整服务日志已从 Docker 恢复。
GPU 进程采样在 19:24:23–19:33:17（Asia/Shanghai）存在约 9 分钟缺口；其余采样只观察到本次 Scheduler 的计算进程。
此监控限制记录在 `validation.json` 与启动目录的 `tracking-recovery.json`，不能据此声称全程连续验证了 GPU 独占性。

复查完整监控时间戳后，还发现 28 段 12–33 秒的短采样间隔，总计 29 段间隔超过 10 秒（包括上面的长缺口）。
多个明显的计时尖峰与短监控空洞重合：16K Cold 最慢 17.67 秒（中位数 2.68 秒）、48K Cold 最慢 36.28 秒（中位数 10.99 秒）、128K Cold 最慢 64.61 秒（中位数 49.99 秒）。
缺少主机 CPU 调度、内存/I/O、GPU 时钟/温度、其他 GPU 和共享驱动资源的连续记录，无法确定停顿来源，也无法排除其他用户作业的影响。
因此本轮可以用于缓存流程正确性验证和性能量级/趋势观察，P95 只能描述本轮观测，尚不能当作无干扰的尾延迟。

线性关系需要按指标区分：16 个 H2D 中位数点的线性拟合 R²=0.999920，最大相对残差约 1.27%；
Cold 全量 Prefill 含注意力的二次工作量，二次拟合 R²=0.999990，不应要求它是直线。
`latency.png` 使用对数纵轴，线性时间随 P 增长也不会在该图上显示为普通直线。
独立审计保存在 `results/prefix-scan-128k/interference-audit/`：`interference_audit.json`、`timing_spikes.csv` 和 `raw_samples_and_fits.png`。
审计只把高于同条件中位数 20% 的计时标作排查线索，没有修改、剔除原始样本或重新生成原统计来使曲线变直。
